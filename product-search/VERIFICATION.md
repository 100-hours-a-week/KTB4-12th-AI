## 2026-09-23 · Kiwi 키워드 분석 적용

Kiwi 0.23.2 / 모델 0.23.0 CoNg로 문서·질의를 같은 방식으로 분석한다. 형태소 분석기는 프로세스당 하나, worker 2개이며 조사·어미를 제외하고 내용 형태소를 사용한다. 영문·숫자 모델명 원형을 함께 보존한다. 두 글자 조각 방식은 제거했다. matchedFields도 같은 형태소 토큰을 기준으로 표시한다.

- 자동 테스트 20개 통과: 기존 12개 및 조사/활용형·모델명·전각 정규화·배치/동시 호출·부분 문자열 오검출·필드 설명 8개 추가.
- 실제 4,231상품의 키워드 인덱스를 다시 만들고 hybrid/lexical/dense 가격 필터, 브랜드·모델명 검색을 확인했다. 기존 카탈로그·dense 벡터 파일 해시는 그대로다.
- 조사 유무 12쌍을 mode=lexical로 비교했을 때 상위 10개 ID 순서 일치가 기존 3쌍에서 Kiwi 12쌍으로 바뀌었다. 이 중 보온병/보온병은 1쌍은 둘 다 0건이다. 원문에 보온병이라는 단어는 없었고 이전 검색은 보온 두 글자로 밥솥·전기포트 등을 반환했다. 결과가 있는 11쌍도 모두 일치했다. 이는 개발용 일관성 검사이며 독립 관련성 평가가 아니다.
- 기동 후 동일한 24회 키워드 HTTP 요청의 중앙값은 기존 3.61ms, Kiwi 1.93ms였다. 한 로컬 환경의 단회 순차 측정이며 운영 지연·일반적 성능 개선을 보장하지 않는다.
- API metadata에 lexicalTokenizer와 새 algorithm 버전을 반환한다. 카탈로그 스냅샷 ID는 유지하고 검색 알고리즘 버전을 구별한다.

별도 로컬 튜토리얼도 Kiwi 코드로 갱신하고 빈 scratch 폴더에서 15개 실행 체크포인트와 20개 테스트를 통과했다. 프로파일러/Backend 실시간 연동과 정답 기반 관련성 평가는 여전히 후속 범위다.
