상품 검색 API

HTTP 요청 예제와 파라미터. 아래 콘솔에서 현재 서버에 직접 요청할 수 있습니다.

연결 확인 중

현재 서버의 주소입니다. 127.0.0.1은 이 맥에서만 연결됩니다. X-Search-Source는 호출 구분용이며 인증 키가 아닙니다.

요청 실행

본문을 수정하면 호출 예제에도 반영됩니다.

POST /v1/search

현재 카탈로그에서 실제로 검색합니다.

실제 응답실행 후 표시됩니다
요청을 실행하면 HTTP 상태와 원본 JSON 응답을 확인할 수 있습니다.
같은 snapshotId와 hits[].productId를 사용합니다.

Python 예제는 httpx 설치가 필요합니다. JavaScript 예제는 Node.js 또는 같은 출처의 브라우저용입니다. 다른 출처의 브라우저를 위한 CORS 설정은 현재 없습니다. /v1 호출은 QA 검색 기록으로 저장되지 않습니다.

엔드포인트

조건에 맞는 상품 후보 검색

헤더: Content-Type: application/json · X-Search-Source: chat 또는 profile (기본 profile). 앱에서는 /v1 경로를 사용하세요. /api 경로는 QA 기록·평가용입니다.

응답 읽기

검색 후보는 hits 배열에 담깁니다. 후보 자체가 없으면 HTTP 200과 status: "NO_MATCH"를 반환합니다. 후보가 있지만 offset이 끝을 넘으면 status: "OK", 빈 hits, nextOffset: null입니다. OK는 상품의 적합성을 보장하지 않습니다.

필드의미
hits[]상품 요약과 순위. productId, sourceProductId, name, brand, categoryId, parentCategoryId, sourceCategoryId, category, categoryGroup, price, description, productType, availability, 이미지 경로
hits[].rank / score순위 / 통합 순위 점수. 적합도 확률이 아닙니다.
lexicalScore / denseScore키워드 점수 / 의미 유사도. lexicalRank, denseRank, matchedFields도 제공. 의미 검색을 실행하지 않으면 denseScore는 null
eligibleCount필터를 통과한 전체 상품 수
candidateCount / hasMore / nextOffset전체 후보 수 / 다음 페이지 여부 / 다음 offset. nextOffset이 null이면 종료합니다.
snapshotId / algorithm상품 내용·벡터·모델·순위 설정의 버전 / 검색 알고리즘 식별자
timingtotalMs, embeddingMs, retrievalMs, cached, embeddingCached

페이지를 넘길 때 같은 조건과 snapshotId를 유지하고 응답의 nextOffset을 다음 offset으로 보내세요. null이면 종료합니다. 검색어가 있으면 키워드·의미 검색은 각각 최대 100개, 통합은 최대 200개 후보입니다. 빈 검색어의 전체 조회에는 이 후보 제한이 없습니다. metadata와 /readyz의 exportGeneratedAt은 Backend export 시각이며 미동기화 시 null입니다. 내용이 같은 export는 시각만 갱신되고 snapshotId는 유지됩니다. 이미지 경로는 검색 서버 기준 상대 URL이므로 서버 주소와 결합하세요. 원본 연결 정보가 없으면 sourceProductId·sourceCategoryId·productType은 null일 수 있고 이미지·원본 링크는 비어 있을 수 있습니다.

상품 ID와 상세 조회

productId는 Backend 초기 적재 SQL에 맞춘 양의 BIGINT입니다. 범위는 1–9223372036854775807이며 JSON 정수로 전달합니다. sourceProductId는 KAKAO_GIFT:… 형태의 원본 수집처 식별자입니다. 운영 DB에 실제 적용된 번호와의 조인은 아직 확인하지 않았습니다.

categoryId와 parentCategoryId는 Backend 기준 정수 번호입니다. sourceCategoryId는 원본 CAT 식별자이며 필터에 사용하지 않습니다. metadata의 categories[].parentId로 상위 분류와 연결합니다.

POST /v1/products에 {"ids": [3670], "snapshotId": "검색 응답의 snapshotId"}를 보냅니다. ids는 1–100개의 정수 배열이고 snapshotId는 선택입니다. 제외 조건의 excludeProductIds도 같은 productId를 사용합니다.

응답은 products, missingIds, snapshotId입니다. 상품 요약에 전체 description, attributes, tags, sourceText, productUrl, descriptionOrigin, tokenCount, embeddingTruncated가 추가됩니다. 없는 ID는 missingIds에 따로 반환합니다.

JavaScript Number는 9007199254740991을 넘는 정수를 정확히 표현하지 못합니다. 큰 ID에는 BigInt와 정밀도를 보존하는 JSON 처리가 필요합니다. 이 콘솔은 JSON 헬퍼의 parseJSON / stringifyJSON을 사용합니다. JavaScript 호출 예제는 요청·응답을 JSON 텍스트로 다뤄 원래 숫자를 보존합니다. Python int는 이 범위를 그대로 처리합니다.

오류 처리

오류 응답은 {"message":"설명","error":{"code":"오류 코드","issues":[{"field":"필드","message":"설명"}]}}입니다. issues는 필요한 경우에만 포함합니다. message를 파싱하지 말고 code로 분기하세요.

상태호출 측 처리
422INVALID_REQUEST / UNKNOWN_CATEGORY / UNKNOWN_BRAND. 잘못된 필드·값을 수정하세요. message와 error.code를 확인하고 error.issues의 field·message로 입력을 수정하세요.
409SNAPSHOT_MISMATCH. snapshotId가 변경됐습니다. 이전 결과와 섞지 말고 새 검색부터 시작하세요.
503SEARCH_BUSY / SEARCH_TIMEOUT / ENCODER_FAILURE / SEARCH_NOT_READY. 준비·실행·부하 오류입니다. 빈 검색 결과로 처리하지 마세요. Retry-After가 있으면 재시도 대기 시간에 반영하세요.

연결 시간 초과와 HTTP 오류를 구분해 처리하세요. 호출 예제는 30초 제한을 사용하며 자동 재시도하지 않습니다. 반복 호출하는 앱에서는 HTTP 클라이언트를 재사용하고 재시도 정책은 한 곳에서 관리하세요.

현재 전체 동시 검색은 최대 12개, profile은 그중 최대 4개입니다. 검색 점수는 추천 확률이 아니며, 최종 상품 선택과 사용자 응답은 호출 앱에서 결정합니다.
