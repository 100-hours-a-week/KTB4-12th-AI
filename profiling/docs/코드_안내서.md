# 프로파일링 코드 안내서 — 처음 보는 사람을 위해

> 2026-09-22 기준. 7.6(접수) → 7.7(콜백)이 **비선호 카테고리만으로** 끝까지 도는 v1 상태. 테스트 43개 통과.
> 그림: [시퀀스](assets/v1-flow.png) · [클래스](assets/class-diagram.png) · 이름 대조: [../이름_대조표.md](../이름_대조표.md)

## 0. 이 서비스가 하는 일 (한 문단)

Backend가 "이 수신자의 비선호 카테고리·취향 문장·최근 리뷰"를 **7.6**으로 보내면, AI는 즉시 `202 접수`를 돌려주고 뒤에서 분석해 **추천 상품 30개**를 골라 **7.7 콜백**으로 Backend에 보낸다. 태그(무엇을 좋아하는지)는 AI가 자기 DB에 보관하고 Backend에는 상품 번호만 보낸다(DR-035). 상품 목록은 Backend의 **7.9 export**에서 받아 AI가 카탈로그로 보관한다. 지금(v1)은 비선호 카테고리만 반영하고, 취향·리뷰를 읽는 모델 단계는 v3에 붙는다.

## 1. 지도 — 어디에 무엇이 있나

```
profiling/
├─ src/profiling/
│  ├─ main.py                  [조립]      앱 시작. 어떤 구현을 끼울지 여기서만 정한다
│  ├─ transport/               [Transport] 3단계 도표의 Transport
│  │  ├─ schemas.py            [바깥 계약] 7.6·7.7·7.9 JSON의 모양 (camelCase, 문서 1 그대로)
│  │  └─ profile_intake.py     [프로파일링 접수] 7.6 라우터: 검증 → 202 → Supervisor → 7.7
│  ├─ profile/
│  │  ├─ types.py              [내부 자료형] 업무 안에서 쓰는 값 (snake_case)
│  │  ├─ ports.py              [포트]       업무가 바깥에 요구하는 "모양" (Protocol)
│  │  └─ pipeline.py           [업무]       요청 한 건의 절차: 변환 → 카탈로그 → 풀 → 저장
│  ├─ runtime/supervisor.py    [Supervisor]  프로파일링 슬롯(동시 1) — 기한·취소는 다음
│  ├─ adapters/                [구현]       "포트 이름 + 방식" 규칙
│  │  ├─ catalog_reader_file.py        CatalogReader — 파일 (팀원 카탈로그 DB 전까지)
│  │  ├─ profile_run_store_db.py       ProfileRunStore — PostgreSQL profile_runs (STORE=db)
│  │  ├─ recipient_profile_store_db.py RecipientProfileStore — PostgreSQL recipient_profiles (STORE=db)
│  │  ├─ profile_run_store_memory.py   ProfileRunStore — 메모리 (STORE=memory · 단위 테스트)
│  │  └─ backend_port_http.py          BackendPort — 7.7 콜백 HTTP 송신 · callback_body(저장·전송 공용)
│  └─ config/settings.py       [설정]       환경변수 → Settings 객체
├─ tools/
│  ├─ fake_backend/            [시험 도구]  가짜 Backend: 7.7 수신 · 7.9 제공 · 시험 콘솔(/console)
│  └─ catalog/make_sample.py   [시험 도구]  예시 카탈로그 생성
├─ tests/
│  ├─ fixtures/catalog_sample.json   예시 카탈로그 111건 (7.9 형식)
│  └─ unit/                    단위 43개 (가짜 adapter · MockTransport · TestClient e2e)
└─ docs/                       이 문서 · 그림 · 환경 설정
```

**[ ] 안의 이름이 "모듈에서의 위치"다.** 큰 틀은 헥사고날(포트·어댑터) 구조:

```
   Backend ──HTTP──▶ [Transport profile_intake] ──▶ [Supervisor 슬롯] ──▶ ┌──────── 업무 (안쪽) ────────┐
                                                                         │ pipeline.py  types.py       │
   파일    ◀── [FileCatalogReader]        ◀── CatalogReader ──────────────┤ ports.py = 바깥에 요구하는 모양 │
   DB      ◀── [DbProfileRunStore]        ◀── ProfileRunStore ────────────┤ recipient_profile.py = 프로필 행 │
   DB      ◀── [DbRecipientProfileStore]  ◀── RecipientProfileStore ──────┤                             │
   Backend ◀── [HttpBackendPort] 7.7      ◀── BackendPort ────────────────┤                             │
                                                                         └─────────────────────────────┘
   규칙 하나: 화살표는 항상 안쪽(업무)을 향한다. 업무 코드는 adapters를 import하지 않는다. 조립(main.py)만 구체 클래스를 안다.
```

## 2. 파일별 — 역할과 함수

### `main.py` [조립 · Composition Root]

| 함수 | 하는 일 |
|---|---|
| `lifespan(app)` | 시작 1회: `get_settings()` → `FileCatalogReader(CATALOG_FILE)` · **`STORE=db`면 `_connect_db()` → `DbProfileRunStore(engine)`·`DbRecipientProfileStore(engine)`, `memory`면 `MemoryProfileRunStore()`·`recipient_store=None`** · `Supervisor(PROFILING_SLOTS)` · `HttpBackendPort(…)`를 만들어 `app.state`에 둔다. 카탈로그 로드가 실패해도 앱은 뜬다(`_NoCatalog` 대역 → 7.6이 503). 종료 시 `backend.close()`·`engine.dispose()` |
| `_connect_db(settings)` | `create_engine(DATABASE_URL, pool_pre_ping=True)` → `select 1` → `alembic_version` 확인. 실패하면 `RuntimeError`로 **앱이 뜨지 않는다** (조용히 메모리로 내려가면 콜백은 나가는데 기록이 없는 상태가 되므로) |
| `_store_health(request)` | `/health`의 `store` 항목: `{backend, connected, migration}` |
| `_NoCatalog` | 카탈로그가 없을 때 그 자리에 두는 대역. `active()`가 항상 `NoActiveCatalog`를 던진다 (Null Object) |
| `_error_response()` | 문서 1 §3 오류 봉투 `{message, error:{code, traceId}}`. 모든 오류 응답이 이 함수를 거친다 |
| `on_validation_error` | Pydantic 검증 실패(FastAPI 기본 422) → **400 INVALID_REQUEST**, 첫 오류 위치를 message에 |
| `on_http_error` | 라우터가 던진 `HTTPException`(401·503…) → 같은 봉투 |
| `on_unhandled` | 잡히지 않은 예외 → 500 |
| `health()` | `GET /health` — 활성 카탈로그 여부·상품 수·Supervisor 슬롯 상태 |

**내일 DB로 바꾸면** `lifespan`의 세 줄만 바뀐다.

### `transport/schemas.py` [바깥 계약 · DTO]

문서 1 v3.2.7의 JSON을 Pydantic으로 옮긴 것. **camelCase**, `extra="forbid"`(모르는 키 거부), 범위 검증.

| 클래스 | 어느 계약 | 핵심 규칙 |
|---|---|---|
| `ProfileExtractRequest` (+`DislikedCategoryDto`·`ReviewDto`) | 7.6 요청 | `recipientUserId>0`, `sourceVersion≥0`, `reviews≤10`, `rating 1..5`, `reviewText` null 가능, `giftPreference` 키 필수(값은 null 가능) |
| `ProfileAccepted` | 7.6 응답 data | `profileStatus="PENDING"` 고정 |
| `ProfileCallbackRequest` | 7.7 요청 | `recommendedProductIds≤30`, `profileStatus="COMPLETED"` 고정, **태그 필드 없음** |
| `ProfileCallbackAccepted` | 7.7 응답 data | |
| `ProductRecord`(+`viewCount`, 없으면 0)·`ProductExportData`·`ProductExportResponse` | 7.9 | 상품 한 건 / export 응답 |
| `SuccessResponse[T]`·`ErrorResponse` | 공통 봉투 | `{message, data}` / `{message, error}` |

이 파일은 **문서가 바뀔 때만** 바뀐다. 업무 코드는 이 클래스를 직접 들고 다니지 않고 `to_internal`로 바꿔 쓴다.

### `transport/profile_intake.py` [Transport]

| 함수 | 하는 일 |
|---|---|
| `get_catalog / get_store / get_backend / get_supervisor(request)` | `app.state`에서 adapter를 꺼내는 의존성. 라우터는 "어떤 구현인지" 모른다 |
| `require_service_token(authorization, settings)` | `Authorization: Bearer <token>` 확인 → 틀리면 401. `SERVICE_TOKEN`이 비어 있으면 검사 생략(로컬) |
| `_error(status, code, message)` | `HTTPException.detail`에 `{code, message}`를 실어 main의 핸들러가 봉투로 만들게 |
| **`extract_and_pool(body, bg, catalog, store, recipient_store, backend, supervisor, settings)`** | 7.6 본체. ① 본문 검증은 FastAPI가 이미 함 ② 토큰 ③ `catalog.active()` 없으면 503 ④ `supervisor.submit(bg, run_and_callback, …)` — 슬롯 안에서 백그라운드 ⑤ **202 반환**. 여기서 HTTP는 끝 |
| **`run_and_callback(rq, catalog, store, backend, pool_size, recipient_store)`** | 백그라운드. `pipeline.profile()` → `RESULT_READY`면 `backend.send_profile_callback()` → 결과(`RunStatus`)를 **`store.save(status=결과, callback_attempts+1)`로 실행 기록에 저장**. 예외는 잡아서 로그(백그라운드에서 죽으면 조용히 사라지므로). FAILED는 콜백 없음 |

### `profile/types.py` [내부 자료형]

| 클래스 | 뜻 | 언제 만들어지나 |
|---|---|---|
| `ProfileRequest` (+`DislikedCategory`·`Review`) | 7.6 요청의 내부판 (snake_case) | `pipeline.to_internal` |
| `ValidationResult` | 검증기 출력: 3축(`likes`·`key_features`·`dislikes`) + 2필드(`preferred_tags`·`disliked_tags`) + 판정 로그 | v1은 `disliked_tags`만 채움 |
| `SearchResult` | 추천 풀: `product_ids ≤30`(순서=순위)·`query_text`·`catalog_version_id` | `pipeline.build_pool` |
| `RunStatus` (StrEnum) | 실행 기록 상태 `RUNNING·RESULT_READY·DELIVERED·SUPERSEDED·FAILED` | 3단계 §10.2. 콜백 결과도 이 값 |
| `ProfileOutcome` | 한 건의 결과 = 저장·콜백의 입력. `status`·`validation`·`search`·`failure_reason`·`validator_version` | `pipeline.profile` |
| `ReviewWithProduct`·`DraftItem`·`ExtractDraft`·`ValidatedTag`·`Decision` | v3(조인·LLM 초안·판정 로그). 실험 JSON 키와 같아 회귀 비교 가능 | v3 |

### `profile/ports.py` [포트 · Protocol]

"업무가 바깥에 요구하는 모양". `typing.Protocol`이라 **상속 없이 메서드 이름·시그니처만 같으면** 어떤 클래스든 꽂힌다 — 진짜 adapter도, 테스트의 가짜도, 팀원 adapter도.

| 포트 | 메서드 | 오늘 구현 → 내일 |
|---|---|---|
| `CatalogReader` | `active() → (catalog_version_id, list[ProductRecord])`, `by_id(product_id)` | `FileCatalogReader` → DB(`catalog_versions`·`products`) |
| `ProfileRunStore` | `save(outcome)`, `get(recipient_user_id)` | `DbProfileRunStore`(`profile_runs`) · `MemoryProfileRunStore`(시험) |
| `RecipientProfileStore` | `upsert(profile)`, `get(recipient_user_id)`, `delete(recipient_user_id)` | `DbRecipientProfileStore`(`recipient_profiles`) |
| `BackendPort` | `send_profile_callback(outcome) → RunStatus` | `HttpBackendPort` |
| `ProfileModel` (v3) | `analyze(prompt, schema, seed) → dict` | 규칙 추출기 · Ollama |
| `Embedder` (v3) | `embed_docs`, `embed_query` | BGE-m3-ko |
| `NoActiveCatalog` | 예외 — 포트가 던지고 Transport가 503으로 | |

### `profile/pipeline.py` [업무 · Application Service]

| 함수 | 하는 일 | 결정 |
|---|---|---|
| `to_internal(body)` | 7.6 DTO(camelCase) → `ProfileRequest`(snake_case). 목록은 항목마다 변환 | 변환은 여기와 `backend.to_callback` 두 곳뿐 |
| `needs_model(rq)` | 취향 문장이 있거나 리뷰가 있으면 True (모델이 읽을 자료가 있음) | 결정 c |
| `build_pool(rq, products, pool_size, catalog_version_id)` | 판매중 · 비선호 카테고리(ID **또는** 이름) 제외 · **조회수(`viewCount`) 내림차순**, 동점은 productId 순으로 앞에서 `pool_size`개. `query_text=""` | 결정 a — 임의성 없음(같은 입력 = 같은 결과). Backend가 초기엔 임의 조회수를 보냄. 팀원 Search가 오면 이 호출이 교체됨 |
| `input_hash(rq)` | 요청을 정규화(비선호 ID 순 정렬)해 sha256. `profile_runs.input_hash` — 같은 (수신자, 버전)에 다른 입력이 왔는지 감지 | 3단계 §10.2 |
| **`profile(rq, *, catalog, store, recipient_store=None, pool_size=30)`** | ⓪ `store.save(RUNNING, input_hash)` ① `catalog.active()` ② `ValidationResult`(v1: 비선호 이름만) ③ `build_pool` ④ `ProfileOutcome(RESULT_READY, input_hash, validator_version="v1-skip")` ⑤ `store.save`(콜백 본문이 DB에 먼저 커밋됨) ⑥ `recipient_store.upsert(from_outcome(rq, outcome))`. **예외를 밖으로 내지 않고 FAILED로 저장·반환** | ⓪ 실패면 아무 행도 없이 FAILED · ⑥ 실패면 실행 기록을 FAILED로 되돌림. [DB_전환_설명.md](DB_전환_설명.md) |
| `_fail(rq, store, reason)` | FAILED 결과(input_hash 포함) 만들고 저장. 콜백은 안 보냄 | |

### `adapters/profile_run_store_db.py` [구현 · ProfileRunStore · PostgreSQL]

| 함수 | 하는 일 |
|---|---|

### `adapters/backend_port_http.py` [구현 · BackendPort]

| 함수 | 하는 일 |
|---|---|
| `to_callback(outcome)` | `ProfileOutcome` → `ProfileCallbackRequest`(7.7 본문). 태그 없음. `RESULT_READY`가 아니거나 `search` 없으면 `ValueError` |

| **`send_profile_callback(outcome) → RunStatus`** | POST 7.7 → `200→DELIVERED`, `409→SUPERSEDED`, `4xx→FAILED`, `5xx·네트워크→RESULT_READY`(재시도 대상). 예외를 밖으로 내지 않음. 로그 한 줄에 수신자·버전·상태·code·개수·소요 시간 |
