## 3. 항목 구조와 표기 규칙

모든 장의 모든 개념 항목은 같은 다섯 토막이다.

```
### N. 항목 이름 (English term)
**개념.**            기초부터 2~6문장
**우리 코드.**       `파일.py:줄–줄` `함수이름` — 발췌 + 한 줄
**왜 이렇게 했나.**  문제 → 제약 → 선택. 숫자가 있으면 출처(§)
**대안과 트레이드오프.**
**확인해 보기.**     명령 하나 또는 질문 하나 (답은 접힘)
```

- 코드 위치는 `파일:줄` 링크에 **함수 이름을 같이** 적는다 — 줄 번호가 어긋나도 찾을 수 있게.
- 기존 문서가 이미 잘 설명한 것은 반복하지 않고 링크한다(§5).
- 말은 기존 문서의 것을 쓴다: 굶음·왕복·슬롯·상한 큐·봉투·대역·보상·재시도/재전송. 영문은 항목 제목에만.

## 6. 틀리기 쉬운 사실 열 가지

1. 검증 순서는 JSON 파싱 → 토큰 → 본문 검증. 토큰도 본문도 틀리면 **401**. ([04 §4](04_통신.md))
2. 202 는 "큐에 들어갔다"이지 "저장됐다"가 아니다. 중복 제출도 202. ([04 §2](04_통신.md))
3. 재고 `unknown` 은 풀에 남는다. 제외는 `unavailable` 만. ([04 §10](04_통신.md))
4. 슬롯 4 는 슬롯 1 의 1.6배(GIL·DB 경합), 4배가 아니다. ([05 §3](05_동시성.md))
5. FAILED 는 Backend 에 보내지 않는다. 5xx·네트워크만 재시도, 4xx 는 FAILED, 409 는 SUPERSEDED. ([04 §7](04_통신.md))
6. `/health` 는 항상 200 — 카탈로그가 없어도, DB 가 끊겨도. compose healthcheck 는 200 만 본다. ([09 §5](09_운영과_도구.md))
7. `io_limiter` 는 스레드 4개가 아니라 **토큰** 4개다. ([05 §5](05_동시성.md))
8. advisory lock 은 세션 잠금이라 COMMIT 과 무관하고, AUTOCOMMIT 이라 `idle in transaction` 이 없다. ([05 §7](05_동시성.md), [07 §6](07_데이터와_DB.md))
9. `callback_attempts` 는 "+1" 이 아니라 시도한 횟수만큼 더한다. `attempt` 는 RUNNING 재저장 때만 +1. ([07 §3](07_데이터와_DB.md))
10. 같은 코드로 어제 185/s, 오늘 125/s — 절대값은 날마다 다르다. ([06 §5](06_병목과_성능.md))

## 7. 낡아질 것과 검사법

줄 번호는 다음 코드 커밋부터 어긋난다. 함수 이름을 같이 적어 두었으니 `grep -n "def 함수이름" src/profiling/파일.py` 로 찾는다. 인용이 얼마나 어긋났는지 보려면:
```bash
git diff --stat a5d1929 -- src/profiling tests tools alembic     # 어느 파일이 얼마나 바뀌었나
```
코드 주석과 실제가 다른 곳(알려진 드리프트)은 [09 §12](09_운영과_도구.md) 표에 있다. 가이드 자체의 구조 검사:
```bash
for f in docs/학습_가이드/0[1-9]*.md; do echo "$f 절 $(grep -c '^## [0-9]' $f) · 확인해 보기 $(grep -c '확인해 보기' $f)"; done
python3 docs/assets/build_doc_tree.py      # 트리 재생성 + 모든 문서가 README 에서 닿는지
```
