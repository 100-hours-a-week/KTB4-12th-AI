### T3 — PENDING 중 재변경

21:06:37 사용자 1이 `[1,2]`로 재저장(200). 35초 뒤 BE: `PENDING`, v1 그대로, `last_changed_at` 21:06:37 기록됨, `pending_since` 그대로. AI에는 새 7.6이 오지 않았다(실행 기록 1건). `RecipientProfile.isDispatchDue`가 PENDING이면 false이고 타임아웃 스케줄러가 없어서 그대로 머문다.

## 4. 원인

| 관찰 | 원인 | 성격 |
|---|---|---|
| 7.7 401 | `InternalRecipientProfileController`·서비스 토큰 필터가 아직 없다(PR3). `SecurityConfig`의 `anyRequest().authenticated()`가 JWT 없는 요청을 거부 | 예정된 미구현. 계약 문제 아님 |
| AI 다운 시 새 번호 반복 | PR2의 `ProfileDispatchService.dispatchOne`은 실패를 로그만 하고 `last_changed_at`을 남긴다 → 다음 틱에 `isDispatchDue` true → `createNextSourceVersion()` +1. `next_retry_at`·`Retry-After` 처리는 5-1 | 예정된 미구현 |
| PENDING 고착 | `findPendingTimeoutCandidates` 질의만 있고 쓰는 스케줄러가 없다(5-2). PENDING이면 새 변경도 발송 대상에서 빠진다 | 예정된 미구현 |
| 대분류 제외가 됐다 | BE는 root 카테고리만 비선호로 저장·전송(`PreferenceSaveService`). AI가 오늘 `ProductRecord`에 대분류를 싣고 `build_pool`이 하위 소분류 전체를 제외하도록 고쳤다(b85fc40) | AI 수정 완료 |

## 5. 해결책 · 요청

**BE (계획 그대로 진행하면 됨)**
1. **PR3** 7.7 수신 — 우리 콜백은 `POST /api/internal/v1/recipients/{recipientUserId}/profile`, `Authorization: Bearer <PROFILING_SERVICE_TOKEN>`, 본문 `{recipientUserId, sourceVersion, profileStatus:"COMPLETED", recommendedProductIds[≤30]}`. 병합되면 이 시험을 그대로 다시 돌려 200·COMPLETED·`recipient_recommended_products` 30행을 확인한다.
2. **5-1** 같은 번호 재시도 + `Retry-After`. AI 503은 `Retry-After: 300`을 보낸다(로컬은 `PROFILING_RETRY_AFTER_S`로 줄일 수 있음).
3. **5-2** PENDING 타임아웃. 그전까지 QA에서 한 수신자가 PENDING에 걸리면 `recipient_profiles` 행을 지워야 다시 나간다(§7 초기화).
4. 콜백의 모르는·삭제된 상품 ID는 버리고 저장, 빈 배열 허용 — [BE_전달 §7 7·8번](BE_전달_2026-09-27.md).
5. 스테이징 디바운스 단축은 **환경변수로 이미 가능**했다(`APP_AIPROFILE_QUIETPERIOD`·`APP_AIPROFILE_MAXIMUMWINDOW`·`AI_PROFILE_DISPATCH_INTERVAL`) — 확인 요청 5번은 이것으로 닫는다.

**AI (완료)** 대분류 제외 · 콜백 5xx 즉시 재시도 · 빈 배열 · 필드표 §6 오류 코드. 남은 것은 PR3 뒤 재시험뿐이다.

## 7. 재현 방법 (직접 확인용)

전제: Docker, `uv`, JDK 25(`brew install openjdk@25`), 두 저장소가 나란히(`KTB4-12th-AI`, `KTB4-12th-BE`).

1. **BE MySQL** — `docker run -d --name seonjalal-mysql-local -p 3306:3306 -e MYSQL_DATABASE=gift -e MYSQL_USER=gift -e MYSQL_PASSWORD=<로컬값> -e MYSQL_ROOT_PASSWORD=<로컬값> mysql:8`
2. **BE `.env`** — `.env.example`을 복사해 DB 값·JWT·HMAC(`openssl rand -base64 32`)·AWS 더미(리전·버킷 문자열이면 기동됨)를 채우고, AI 연동 값과 로컬 단축값을 넣는다:
   `AI_PROFILE_BASE_URL=http://localhost:8000` · `PROFILING_SERVICE_TOKEN=local-profiling-token` · `AI_PROFILE_DISPATCH_INTERVAL=10s` · `APP_AIPROFILE_QUIETPERIOD=10s` · `APP_AIPROFILE_MAXIMUMWINDOW=60s` · `SCHEDULING_ENABLED=true`. `.env`는 커밋하지 않는다.
3. **BE 기동** — `cd KTB4-12th-BE && set -a && . ./.env && set +a && JAVA_HOME=/opt/homebrew/opt/openjdk@25/libexec/openjdk.jdk/Contents/Home ./gradlew bootRun` → `curl :8080/actuator/health`가 `UP`. 첫 기동에 Flyway가 시드까지 넣는다(상품 4,231).
4. **AI 기동** — `cd KTB4-12th-AI/profiling && docker compose up -d && uv run alembic upgrade head`(카탈로그는 이미 적재돼 있어야 — [README §3](../README.md)) 후
   `PROFILING_SERVICE_TOKEN=local-profiling-token PROFILING_BACKEND_BASE_URL=http://localhost:8080 PROFILING_CATALOG_SOURCE=db uv run uvicorn profiling.main:app --port 8000` → `curl :8000/health`가 `catalog.active: true`.
5. **시험** — 자동: `uv run python tools/be_integration/drive.py --with-ai-down --out result.json`(profiling 디렉터리에서). 수동이면:
   - 로그인 `POST :8080/auth/login {"email":"minsoo.kim@gift.local","password":"<시드 V5 값>"}` → `data.accessToken`
   - 비선호 저장 `PUT :8080/preferences/dislike-categories {"categoryIds":[1]}` (헤더 `Authorization: Bearer <accessToken>`) — Postman이면 BE `docs/postman` 컬렉션의 로그인 뒤 같은 요청
   - 20초 안에 AI 로그에 `7.6 접수 recipient=1 …` → `RESULT_READY pool=30/30` → `7.7 콜백 …`이 찍힌다
6. **확인 SQL**
   - BE: `select recipient_id, profile_status, source_version, analyzed_source_version, retry_count, last_changed_at, pending_since from recipient_profiles;`
   - AI: `select recipient_user_id, source_version, status, error, callback_attempts, callback_payload->'recommendedProductIds' from ai_profile.profile_runs order by updated_at desc;`
   - 대분류 제외 검증(BE MySQL, 위 30개 ID로): `select c.parent_id, count(*) from products p join categories c on c.id=p.category_id where p.id in (…) group by c.parent_id;` → 비선호 대분류가 없어야 한다
7. **초기화(다시 돌릴 때)** — BE: `delete from recipient_recommended_products where recipient_id=1; delete from recipient_profiles where recipient_id=1; delete from user_dislike_categories where user_id=1;` · AI: 드라이버가 끝에 지운다(`--keep`이면 남김). 다른 시드 사용자(3~11)를 쓰면 초기화 없이 새로 돌릴 수 있다.
