# 이슈 기록 — 발견한 문제를 올리기 전에 정리하는 곳

코드를 검토하다 문제를 찾으면 **발견한 시각으로 폴더를 하나 만들고** 거기에 문서 한 장과 그림을 둔다. GitHub 이슈나 트러블슈팅 글은 이 문서를 그대로 옮겨 쓴다.

## 색인 (최신이 위)

| 폴더 | 무엇 | 심각도 | 상태 |
|---|---|---|---|
| [2026-09-27_1633_advisory-lock](2026-09-27_1633_advisory-lock/) | `run_lock` 3건 — 트랜잭션을 열어둔 채 작업 · 잠금 키 32비트 절단 · 문서-동작 불일치 | 🔴🟡🟡 | 열림 |

## 규칙

**폴더 이름** — `YYYY-MM-DD_HHMM_<짧은-영문-슬러그>`. 시각까지 넣어야 같은 날 두 번 발견해도 순서가 남고, 슬러그가 있어야 `ls` 만으로 무엇인지 안다.

**한 폴더 = 한 번의 발견.** 같은 검토에서 같은 곳의 문제가 여럿 나오면 한 폴더에 두되, **문제마다 절을 나누고 절마다 아래 머리말을 전부 갖춘다** — 그래야 절 하나를 이슈 하나로 그대로 옮긴다.

**문서 (`README.md`) 머리말**

| 머리말 | 뜻 |
|---|---|
| 머리표 | 발견 시점 · 발견 방법 · 대상 코드(파일·함수·들어온 커밋) · **상태**(열림 / 해결 · 커밋) · 심각도 |
| 문제 이름 | 한 줄. 이슈 제목이 된다 |
| 문제 정의 | 무엇이 어떻게 틀렸나 — **실측 근거**(명령·출력)를 붙인다. 추측이면 추측이라 적는다 |
| 문제 원인 | 왜 생겼나. "누가"가 아니라 "어떤 가정·누락"인지 |
| 연관된 기능 | 이 문제가 실제로 건드리는 기능과, 지금은 왜 안 보이는지/언제 드러나는지 |
| 문제 그림 | mermaid 한 장. 정상 흐름이 아니라 **틀어지는 순간**을 그린다 |
| 예상 해결책 | 고치는 방법 + 그것을 고정할 시험 + 손볼 문서. 번호를 매긴다 |
