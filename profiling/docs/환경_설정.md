# 개발 환경 설정 — 무엇을 어떻게 고정했고 왜 그런가

합칠 때 버전 충돌을 피하려면 "어떤 값을 왜 골랐는지"가 남아 있어야 한다. 팀원 쪽과 다른 값이 있으면 이 문서를 놓고 맞춘다.

## 1. 도구 — uv

| 항목 | 값 | 이유 |
|---|---|---|
| 패키지·가상환경 관리 | **uv** | Python 설치, 가상환경, 의존성 해석, 락 파일을 한 도구가 다 한다. `pip` + `venv` + `pip-tools`를 따로 쓰지 않아도 되고 속도가 빠르다 |
| 설정 파일 | `pyproject.toml` 하나 | 의존성·pytest·ruff 설정을 한 파일에 둔다. `requirements.txt`는 만들지 않는다 |
| 락 파일 | `uv.lock` — **커밋한다** | 모든 의존성의 정확한 버전이 기록된다. 팀원이 `uv sync` 하면 내 환경과 같은 버전이 설치된다. 이게 없으면 같은 `pyproject`라도 날짜에 따라 다른 버전이 깔린다 |
| 가상환경 | `.venv/` — **커밋하지 않는다** | `uv init`이 만든 `.gitignore`에 이미 들어 있다 |
| 실행 | `uv run <명령>` | 가상환경 활성화 없이 락 파일 기준으로 실행한다 |

## 2. Python 버전 — 3.12 고정

| 항목 | 값 |
|---|---|
| `.python-version` | `3.12` |
| `pyproject.toml` `requires-python` | `>=3.12` |

**왜 3.12인가**
- `uv python install`을 버전 없이 실행하면 최신 안정판(지금은 3.14)이 깔린다. 그러나 임베딩 adapter가 쓸 `torch`·`sentence-transformers`는 최신 Python용 휠이 늦게 나와서, 3.14에서는 그 단계에서 설치가 막힐 수 있다.
- 3.12는 이 패키지들이 안정적으로 지원하고, 우리가 쓰는 문법(`StrEnum`, `X | None`, `list[int]`)도 전부 된다.
- 3.11 이하로 내리지 않는 이유: `StrEnum`(3.11+)과 타입 문법을 그대로 쓰기 위해서. 팀원 코드가 3.11이면 `requires-python`을 `>=3.11`로 낮추고 `StrEnum` 한 곳만 확인하면 된다.

**합칠 때 규칙**: Python 버전은 레포 전체에 하나. `.python-version`이 둘이면 낮은 쪽으로 맞추고, 이 문서의 이유를 보고 결정한다.

## 3. 의존성 — 위키 확정 스택 그대로

AI 위키 "기술 스택"(2026-09-14 확정)의 이름을 그대로 쓴다. 다른 패키지로 대체하지 않는다.

| 패키지 | 용도 | 근거 |
|---|---|---|
| `pydantic` | DTO·내부 자료형 | FastAPI가 쓰는 것과 같은 계열. 실험 JSON을 그대로 읽는 alias 기능 |
| `pydantic-settings` | 환경변수 설정 객체 | 실험 `config.json` 값을 환경변수로 옮김 |
| `fastapi` + `uvicorn[standard]` | 7.6 접수 엔드포인트 | 위키 확정 |
| `sqlalchemy` + `psycopg[binary]` | DB adapter | 위키 확정(psycopg 3). `psycopg2`가 아님 |
| `alembic` | 마이그레이션 | 위키 확정 |
| `httpx` | 7.7 콜백 송신·7.9 export 호출 | 위키 확정. `requests`가 아님 |

**개발 전용** (`--dev`): `pytest`, `pytest-asyncio`, `ruff`. 운영 이미지에 들어가지 않는다.

**별도 그룹으로 둘 것** (`--group embed`): `sentence-transformers`(+`torch`). 2GB가 넘어 기본 설치에서 빼고, 임베딩을 쓰는 곳에서만 `uv sync --group embed`로 받는다.

**아직 넣지 않는 것과 이유**
- 검색(`bm25s` 등): Search는 팀원 모듈
- 모델 클라이언트(`ollama`, `openai` 등): 모델 결정 뒤 Model adapter에서
- `pgvector` Python 패키지: 임베딩 테이블 마이그레이션 때

## 4. 버전 지정 방식

- `uv add 패키지`로 넣으면 `pyproject.toml`에는 `>=현재버전` 하한만 적히고, 정확한 버전은 `uv.lock`에 잠긴다. **상한(`<`)은 적지 않는다** — 합칠 때 팀원 것과 교집합이 안 나오는 원인이 된다.
- 버전을 올릴 때는 `uv lock --upgrade-package 이름`으로 한 개씩. 전체 업그레이드(`uv lock --upgrade`)는 합친 뒤 둘이 같이 한다.

## 5. 위치 — 지금은 `profiling/`, 합칠 때 레포 루트

각자 개발한 뒤 합치기로 했으므로 `pyproject.toml`·`uv.lock`·`.python-version`은 지금 `profiling/` 안에 둔다. 합칠 때는:
1. 레포 루트에 `pyproject.toml` 하나로 합친다(의존성은 합집합, Python 버전은 §2 규칙).
2. `uv lock`을 다시 만들어 루트 `uv.lock` 하나만 남긴다.
3. `profiling/src/profiling/…`은 루트 `src/app/profiling/`으로 옮기고 import 경로만 바꾼다.

## 6. 설치 순서 (처음 받았을 때)

```bash
cd profiling
uv python install 3.12        # 없으면
uv sync                       # uv.lock 기준으로 .venv 생성 + 설치
uv run pytest                 # 확인
```

`uv init`·`uv add`는 **반드시 `profiling/` 안에서** 실행한다. 다른 폴더에서 실행하면 그 폴더에 새 프로젝트가 생긴다(2026-09-18에 한 번 그랬다).

## 7. pyproject.toml에 손으로 넣는 블록

`uv init`이 만들지 않는 설정. `[project]` 아래에 추가한다.

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
pythonpath = ["src"]

[tool.ruff]
line-length = 120
target-version = "py312"

[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP"]
```

- `pythonpath = ["src"]` — 테스트에서 `from profiling import …`가 되게
- `line-length 120` — 한글 주석·docstring이 길어서 88은 자주 걸림
- `select` — 문법 오류(E·F), import 정렬(I), 흔한 버그(B), 최신 문법 권고(UP)만. 팀원과 합칠 때 늘리거나 줄인다
