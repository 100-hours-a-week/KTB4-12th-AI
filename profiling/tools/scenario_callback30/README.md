# 프로파일링 코어 30개 상품 콜백 검증 — `tools/scenario_callback30/`

가상 수신자(엑셀)를 프로파일링 코어에 넣어 **입력 → 점수 책정 → 30개 추천 → 7.7 콜백**을 한 번에 보고 검사한다. 돌릴 때마다 화면에 결과가 나오고 `out/`에 엑셀·JSON이 남는다.

```bash
cd profiling
docker start profiling-ai-db && uv run alembic upgrade head      # DB 카탈로그(ai_catalog, BE 번호) 필요
uv run python -m tools.scenario_callback30.run                  # 두 모드(exclude · penalty) 모두
uv run python -m tools.scenario_callback30.run --modes penalty --top 10 --keep
uv run pytest tests/integration/test_scenario_callback30.py -q  # 같은 실행을 시험으로(실패 검사 이름을 보여 줌)
```

| 파일 | 역할 |
|---|---|
| `scenarios.xlsx` | **입력** — 사용자(비선호 · 취향 문장) · 리뷰(상품 · 별점 · 글) · 기대(검사). 엑셀을 직접 고쳐 사람을 늘리거나 기대를 바꾼다. 쓰는 법은 '설명' 시트 |
| `run.py` | 실행기 — 앱 전체를 서버 없이(TestClient) 띄워 7.6 을 보내고, **진짜 `HttpBackendPort`가 보내는 7.7 HTTP 요청**을 MockTransport 로 받아 기록 |
| `out/` | 결과(커밋 안 함) — `시나리오_결과_<시각>.xlsx` · `.json` |

## 무엇을 타나

7.6 POST → 202 → Supervisor 워커 → `pipeline.profile()`(`category_scores` → `rank_products`/`build_pool` → 30개) → PostgreSQL(실행 기록 · 프로필 · 리뷰) → 7.7. LLM 호출 없음, 서버 따로 안 띄움. 시험 수신자 번호: 제외 모드 9,300,001~ · 감점 모드 9,310,001~(전후로 지움, `--keep`이면 남김).

## 검사

**자동(모든 실행 13개 + D 3개):** 7.6 202 · 7.7 콜백 1회·경로·토큰 · 본문 계약(`ProfileCallbackRequest`, 모르는 필드 금지) · 개수 = min(30, 후보) · 중복 없음 · 카탈로그·재고 · **재현성**(콜백 30 = 실행 기록 30 = 같은 입력으로 코드가 고른 30 — `pipeline.make_pool`) · 비선호(제외: 0개 / 감점: 비선호 아닌 상품 뒤에만) · **소분류 점수 독립 재계산**(리뷰·카탈로그에서 직접) · **점수 공식 독립 재계산**(인기 + 편향 + 감점, 오차 < 1e-9) · 저장된 점수 = 코드 점수 · 리뷰 행(중복 제거·자리·지문) · **원문 미저장**(리뷰 글·취향 문장이 DB 어디에도 없음) · 실행 기록 DELIVERED. **D(`POOL_STRATEGY=d`, 기본)일 때:** 비선호 아닌 상품으로 채울 수 있으면 비선호 0 · 한 소분류 최대 10 · 같은 브랜드 + 모델 코드 중복 없음.

**리뷰한 상품 미추천**(모든 실행, 10-12): 콜백 30개에 그 사람이 리뷰한 상품(이미 받은 선물)이 없음.

**D 독립 판정(`verify_d.py`, 10-12):** 재현성(콜백 = `make_pool`)은 같은 코드를 다시 부르는 것이라 D 안의 버그를 못 잡는다. 그래서 `profiling.selection` 을 부르지 않고 **명세 수식만으로** 콜백 30개를 검사한다 — ① 상수가 명세(λ 0.7 · 한 소분류 10 · 태그당 50 · 유사도 2 · 특징 ½)와 같은가 ② **MMR 단계**: 고른 상품마다 그 시점 받아들일 수 있는 후보 중 MMR 최대였나(태그가 있을 때) ③ **채우기 단계**: 점수 순서 · 상한 → 상한 없이 → 비선호 순서 그대로인가. 여기에 **입력 변형** 두 가지(같은 입력 두 번 → 같은 결과 · 비선호를 하나 더 → 그 대분류 상품이 사라짐). 일부러 버그를 심어 확인: 채우기 순서를 바꾸면 10/10 · MMR 중복 감점을 빼면 7/7 을 잡고, 재현성 검사는 둘 다 통과했다(못 잡음).

**기준 파일(`golden_d.json`, 관찰):** 태그 끔 · D 의 콜백 30개. 다르면 의도된 변경인지 사람이 본다. 의도된 변경 뒤엔 `--save-golden` 으로 새로 쓴다.

**시나리오 기대('기대' 시트):** 종류 `상위N_최소` · `상위N_최대` · `조회수순` · `모드간_동일` · `순위_앞섬` · `이름_최소` · `종수_최소` · `태그_포함` · `태그_제외` · `태그_없음`. 열 **조건**(`태그=끔` · `태그=켬` · `고르기=d` · `모델=…`, 비면 언제나) · **등급**(필수 = 실패하면 하네스 실패 · 관찰 = 보고만, 모델 · 프롬프트 품질 비교용) · **성격**(계약 · 별점 · 회귀 · 태그품질 · 취향 · 섞임). 10-12 결과: 태그 끔 448/448 · gemma4:12b 필수 462/462 · 관찰 44/44 · qwen3.5:9b 필수 462/462 · **관찰 28/44**(품질 문제가 계약 실패와 섞이지 않고 따로 보인다).

## 2026-10-12 실행

20건(10명 × 2모드) · 검사 300/300 통과 · 7.7 콜백까지 p50 ≈ 11ms · 전체 1.0초. **발견:** 리뷰에 양의 편향이 있는 6명 모두 30개를 그 소분류가 **전부** 차지한다. 원인은 정규화가 아니라 **선택성** — 30개는 카탈로그 4,231개의 0.7%인데 편향 +0.67 은 순위로 전체의 1/3을 끌어올리는 크기라, 편향 소분류 상품은 조회수 중간만 돼도 편향 없는 1위를 넘는다. 인기를 순위 백분위로 바꿔도(10-12) 결과는 같았다(지금 조회수는 고르게 퍼져 두 방식 값이 거의 같음). 가중치 · 소분류 상한 시뮬레이션과 결정할 것은 [docs/시나리오_검증_결과_2026-10-12.md](../../docs/시나리오_검증_결과_2026-10-12.md).
